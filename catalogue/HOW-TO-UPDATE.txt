KITCHEN SINK CATALOGUES: THE WEBSITE'S COPY
===========================================

This folder holds what the website (index.html) shows and offers for download:

  MTJ_Granite_Kitchen_Sink_Catalogue.pdf              Volume 01, Granite, English
  MTJ_Granite_Kitchen_Sink_Catalogue_ID.pdf           Volume 01, Granite, Bahasa Indonesia
  MTJ_Stainless_Steel_Kitchen_Sink_Catalogue.pdf      Volume 02, Stainless Steel, English
  MTJ_Stainless_Steel_Kitchen_Sink_Catalogue_ID.pdf   Volume 02, Stainless Steel, Bahasa Indonesia
  img/pages/<granite|stainless>-<en|id>-1..3.jpg      three pages of each PDF, for "Look inside"
  img/here.gif                                        a 1-pixel marker: when the site is opened from a disk,
                                                      it tells the site that this folder is present

These PDFs are the presentation (screen) editions from catalogues/pdf/, renamed to the file names the site
expects. The print editions, with 3 mm bleed, are only in catalogues/pdf/.


TO UPDATE THEM
--------------
1. Rebuild the catalogues with the generator in catalogues/source/ (see catalogues/README.md):

     layout/make_catalogues.sh <renders> <photos> <logos> <work dir> <pdf dir>

2. Copy them to the website:

     python layout/publish_site.py <pdf dir> <work dir> <website folder>

   This copies the four PDFs here and makes the look-inside pictures. It also writes into index.html each
   PDF's page count and file size (KS_PDF_META) and every model's page number (KS_PDF_PAGES), so that
   "View in the catalogue" opens the right page.

3. Commit and push. GitHub Pages publishes the site from the main branch. A change pushed to a claude/...
   branch goes live by itself: .github/workflows/publish-to-website.yml merges it into main.

If you replace a PDF by hand instead, keep the same file name. Then update its page count and file size in
KS_PDF_META in index.html, and the model page numbers in KS_PDF_PAGES if any models moved to different pages.
